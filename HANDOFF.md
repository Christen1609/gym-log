## The one architectural rule — do not break this

**Code computes every number. The LLM only judges and phrases them.**

- `src/lib/gymlog.ts` owns all arithmetic in plain deterministic TypeScript:
  est 1RM (Epley, `weight × (1 + reps/30)`), percent change, RPE trend, and the
  thresholds deciding Progressing / Grinding / Stalling / Regressing.
- `src/lib/coach.ts` is `server-only`. It receives already-computed figures and
  instructs the model never to state a number it wasn't given. Falls back to
  fixed copy when `GEMINI_API_KEY` is unset.
- The date comes from the system clock and is passed to the model as a fact.
  Never ask the model what day it is.
- The UI keeps the halves visually separate: computed figures sit under a
  `COMPUTED` label in tabular figures; the coach's read sits below a rule next
  to an avatar. A reader should be able to see which half the model wrote
  without reading it.

## Zero-config is a deliberate property

The app runs fully with **no environment variables**: bundled seed history,
fixed coach copy, localStorage persistence. Each env var upgrades one layer.
`src/lib/supabase.ts` exports `isSupabaseConfigured` and every Supabase path is
behind that flag. **Preserve this.** Don't make Supabase or Gemini mandatory.

`.env.local` (gitignored) currently holds the Supabase URL + anon key.
`.env.local.example` documents every variable.

## Gotchas — each of these cost real debugging time

1. **Never put refs in the `useGymLog` return object.** React 19's
   `react-hooks/refs` lint rule flags *any* property access on an object
   containing a ref during render, which produced ~13 spurious errors across
   unrelated lines. Refs are component-local; the hook exposes
   `submitText(text: string)` instead of taking an input ref.

2. **Never read `localStorage` in a `useState` initializer.** It mismatches SSR
   output and throws a hydration error. Persisted state is applied in a
   one-time post-hydration effect gated by a `hydrated` flag, which also gates
   the persist-write effect so it can't clobber storage with defaults on first
   paint. The `react-hooks/set-state-in-effect` disable there is deliberate and
   documented — it's the rule's stated exception.

3. **Postgres views need `security_invoker = true`.** Views run as their owner
   by default, silently bypassing RLS on the underlying tables. Both
   `last_performance` and `set_trend` set it. Any new view must too.

4. **`readOut()` takes the history to compute over**, defaulting to the bundled
   seed. It returns an empty flat trend for an exercise with no history rather
   than throwing, and Today/Progress filter out exercises with none — so a new
   account renders instead of crashing.

5. **`db.ts` reconciles two shapes.** The schema stores one row per set; the UI
   wants one entry per exercise per session with a set count. `loadHistory()`
   collapses them (reporting the session's heaviest set as its load);
   `saveSet()` reverses it, reusing today's session if one exists and continuing
   set numbering rather than restarting at 1.

6. **Icons were generated by screenshot, not drawn.** The LOCK/IN wordmark in
   `public/` was rendered from HTML via Chrome DevTools at 1024/512/256 then
   resized with `sharp`. The design doc pins exact metrics (Figtree 700,
   line-height 0.82, -0.05em tracking); reproducing that as hand-written SVG
   drifts. Regenerate the same way if sizes change.

## Credentials

Secrets are **not** in the repo. `.env.local` holds the Supabase URL and anon
key; Vercel holds the same two for Production and Development. The anon key is
safe to expose — RLS is what protects the data.

Preview-environment env vars on Vercel were **not** set (the CLI kept rejecting
non-interactive input). Production works; preview deploys from PRs would lack
Supabase config. Fix in the Vercel dashboard if you need PR previews.

Ask the user for any credential you need — do not go looking for them.
